Applies only to a volume whose last tick hit the {{ s.maxRecordsPerTick | grouped }}-record cap, and only until it is caught up. The change journal is a fixed-size circular buffer, so a volume that drains slower than it writes eventually loses the records it has not read. At the {{ (86400 / s.intervalSeconds).toFixed(0) }}-tick day above, that works out at {{ (s.maxRecordsPerTick / s.intervalSeconds).toFixed(0) }} records a second.

10% 100%
A tick defers if system CPU is above this when it fires. The scan itself runs at very low I/O priority and yields regularly, so this is about not adding to a load that is already there.
Also defer when
Deferred ticks are recorded with their reason and never skipped silently — the log below is the evidence. The change journal keeps recording while Strata sleeps, so a deferral costs resolution in the timeline rather than data.
I/O priority
Per-thread rather than per-process, so a scan cannot throttle the API serving this page. Turn it off only to measure what it costs.
History kept thinned nightly, never deleted outright
Thin old history {{ s.retentionEnabled ? 'on' : 'off' }}
Off keeps every measurement for ever, and the database grows without bound. On, a directory keeps its newest measurement in each bucket below — so a size is always known at any past moment, just to a coarser minute the further back you look. Nothing is ever deleted without something older still standing behind it.
